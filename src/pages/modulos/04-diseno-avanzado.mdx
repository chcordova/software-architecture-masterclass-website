    private void validate() {

export const codeExceptionHandler = `package com.company.attendance.infrastructure.input.web;

import com.company.attendance.domain.exception.InvalidAttendanceException;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.bind.annotation.ExceptionHandler;

@RestControllerAdvice
public class GlobalExceptionHandler {

    // TRADUCTOR: Captura la excepción pura del dominio y la convierte en un contrato HTTP 400
    @ExceptionHandler(InvalidAttendanceException.class)
    public ResponseEntity<ErrorResponseDto> handleDomainException(InvalidAttendanceException ex) {
        ErrorResponseDto error = new ErrorResponseDto("BAD_REQUEST", ex.getMessage());
        return ResponseEntity.badRequest().body(error);
    }

}`;

# Módulo 4: Diseño Avanzado (El Mundo Real)

La teoría de los Puertos y Adaptadores es elegante en papel, pero su implementación real exige resolver problemas complejos de control de dependencias, validaciones e intercepción de errores.

Veamos cómo el repositorio `attendance-service-hexagonal` resuelve los mayores dolores de cabeza de los Arquitectos de Software.

## 4.1 Fronteras de Validación (Validation Boundaries)

Un error común al implementar Hexagonal es acoplar el Dominio a las anotaciones de Jakarta Validation (`@NotNull`, `@Size`). Si hacemos esto, nuestro dominio pasa a depender de una especificación externa.

**La Solución:** Dividir la validación en dos barreras defensivas.

1. **Barrera de Transporte (Infraestructura):** Validamos el formato de los datos que entran por HTTP (ej. un JSON válido, tipos numéricos) usando anotaciones propias como `@ValidEmployeeId`.
2. **Barrera de Dominio (Core):** El objeto de negocio asume que el mundo exterior es hostil e inválido, por lo que vuelve a evaluar las reglas, pero esta vez con enfoque de negocio.

## 4.2 Traducción de Excepciones (Exception Translation)

Si el Dominio detecta una regla rota (ej. "Fecha en el futuro"), lanzará una excepción nativa: `FutureDateException`.

**El problema:** El Dominio no sabe qué es un "HTTP 400 Bad Request", ni le importa.
**La solución:** El adaptador de infraestructura (`GlobalExceptionHandler` con `@RestControllerAdvice`) actúa como un "Traductor de Idiomas", capturando el error del dominio y transformándolo en un DTO estandarizado para el cliente REST.

## 4.3 La Prueba de Fuego: Control de Dependencias a Nivel Compilación

La forma definitiva de auditar si tu Arquitectura Hexagonal es real o es un "fraude", es mirar los archivos de compilación (`pom.xml` o `build.gradle`).

En una arquitectura verdaderamente desacoplada, si extrajeras la carpeta `domain/` a su propio módulo `.jar`, su archivo de dependencias debería estar casi vacío (o depender solo de librerías utilitarias como Lombok o Apache Commons). **Está estrictamente prohibido importar dependencias de Spring Boot, JPA o Web en el núcleo.**

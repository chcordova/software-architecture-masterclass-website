# Módulo 3: Arquitectura Hexagonal y Data Fidelity

La Arquitectura Hexagonal (_Ports and Adapters_), propuesta por Alistair Cockburn, invierte las dependencias: la UI y la Base de Datos son "plugins" que dependen del Dominio, nunca al revés.

## Eric Evans y la Fidelidad de Datos (Data Fidelity)

En el diseño original de Hexagonal, Cockburn veía a la base de datos como "solo un adaptador más". Sin embargo, **Eric Evans (creador de DDD)** corrigió esto en sistemas distribuidos.

La **Data Fidelity** dicta que la base de datos no es una maquinaria separada; sus esquemas relacionales deben mutar y reflejar estrictamente las reglas del dominio (_Bounded Context_). Es por eso que, aunque separemos el adaptador JPA en \`infrastructure/\`, las validaciones e invariantes de datos viven y se evalúan obligatoriamente en la entidad pura de Java dentro de \`domain/\`.
